# Security and trust model

**Classification:** development baseline, not a hardened hostile-site or multi-tenant service.

## 1. Assets

- Ginger OS credentials and local files
- remote Ollama credentials and inference endpoint
- browser process and task contexts
- task objectives, clarifications and outputs
- captured page content and evidence files
- task logs and operational configuration

## 2. Trust boundaries

| Boundary | Input trust | Required control |
|---|---|---|
| User/Ginger to API | Authenticated intent not yet guaranteed | Local bind; authentication and authorization before network exposure |
| Decider/model to orchestrator | Untrusted proposal | Strict schema validation; bounded plans; no permission granting |
| Website to browser/extractor | Untrusted content | Request policy, bounded capture, prompt-injection resistance |
| Browser to evidence store | Runtime-generated observations | Trusted IDs, immutable writes, size limits, safe filesystem permissions |
| Report to Ginger memory | Untrusted candidate knowledge | Separate approval, provenance and retention policy |
| Ginger OS to Ollama | Trusted operator-configured endpoint | Private network/HTTPS, authentication, allowlisted endpoint |

## 3. Threats and mitigations

| Threat | Current mitigation | Remaining gap |
|---|---|---|
| Model invents browser evidence | Evidence IDs generated by EvidenceStore | Report-level provenance validation incomplete |
| Model proposes unsafe URL | PolicyEngine URL validation | DNS/redirect race and infra-level egress controls still needed |
| Website prompt injection | Page content is treated as untrusted data in prompts | Full adversarial prompt-injection test suite needed |
| Cross-task data leakage | New BrowserContext per task; minimized context packets | Durable storage access controls not implemented |
| Internal network access / SSRF | Scheme, hostname, port and DNS/IP checks; route interception | Not a substitute for network namespace/firewall/proxy egress enforcement |
| Dangerous browser actions | Read-only execution; downloads disabled | Future interaction capabilities require explicit grants and tests |
| API abuse | Localhost-bound Docker port by default | No authentication, quotas or multi-user authorization |
| Evidence tampering | Atomic write and generated IDs | Filesystem permissions, integrity hashes and retention controls needed |
| Sensitive data capture | Bounded visible-text capture | Redaction/classification and deletion lifecycle not implemented |

## 4. Mandatory security rules

1. Models propose; trusted code validates and executes.
2. Never pass secrets to model context or browser page content.
3. Never let page content change policy, permissions or tool availability.
4. Validate every navigation and every network request; revalidate redirects.
5. Keep browser egress restricted at infrastructure level, not only in Playwright.
6. Keep downloads, form submission, payments and state-changing actions disabled unless a separately reviewed capability is introduced.
7. Do not expose the current API to untrusted networks.
8. Keep credentials in environment/secret management, never in source or task payloads.
9. Bound time, output tokens, plan steps, page text, link candidates and evidence sizes.
10. Log security denials without logging secrets or unnecessarily duplicating sensitive page content.

## 5. Browser isolation requirements before hostile-site use

Before visiting untrusted sites on behalf of untrusted callers, add:
- per-task process or container isolation;
- non-root execution and read-only filesystem where feasible;
- CPU, memory, process and wall-clock limits;
- network namespace or egress proxy with explicit destination policy;
- DNS rebinding and redirect-resistant destination validation;
- browser sandbox verification;
- ephemeral storage and strict cleanup;
- authenticated caller identity, per-user task authorization and quotas;
- security event audit trail.

## 6. Trust semantics

- **Observed:** directly captured from a source at a retrieval time.
- **Reported:** a source makes the claim; Night Walker has not independently verified it.
- **Derived:** deterministic transformation from cited evidence.
- **Inferred:** reasoned conclusion; assumptions and uncertainty must be disclosed.
- **Verified:** reserved for a defined verification procedure with independent corroboration. Do not use as a synonym for “the page loaded”.

Night Walker's current page title, heading and visible text capture is observational evidence only.
